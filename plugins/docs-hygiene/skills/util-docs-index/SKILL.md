# util-docs-index — OKF folder index generator

Generate or refresh an **OKF `index.md`** for a folder: a deterministic script does the
parsing and formatting; you (the agent) supply a concise one-line summary for any document
that doesn't already carry one. The result is a consistent, OKF-conformant directory listing
that an OKF consumer (or a human, or another agent) uses for progressive disclosure.

## Canonical definition

`index.md` is an [OKF v0.1](https://github.com/GoogleCloudPlatform/knowledge-catalog/blob/main/okf/SPEC.md)
**reserved file** — a per-directory listing, not an artefact concept document. It carries **no
artefact frontmatter**; only the **bundle root** `docs/index.md` carries `okf_version`. OKF
prescribes no body schema, so this skill defines a **consistent table** the generator always
emits (see the `metamodel` skill's `references/artefact-frontmatter.md` §Reserved files).

## Boundary vs the `metamodel` skill's Scaffold mode

- **the `metamodel` skill's Scaffold mode Mode 3** owns the **bundle-root stack-progress dashboard** (the
  ✅/🔄/⬜ table keyed to the metamodel build steps). Prefer it for `docs/index.md`.
- **This skill** produces a **generic per-folder listing with per-doc summaries** for **any
  folder** — sub-folders (`docs/domain/`, `docs/architecture/decisions/`, …) and non-metamodel
  trees. It reads whatever docs are actually present; it does not know the build order.

## The deterministic script

`scripts/gen_index.py <folder> [--check] [--okf-version X]` (stdlib only):
- lists the folder's concept docs (excludes reserved `index.md`/`log.md`/`README.md`), sorted;
- reads each doc's frontmatter → `Type | Document (linked title) | Status | Summary`;
- **summary source**: the doc's OKF `description` field → else a preserved manual cell → else a
  `_TODO summarize_` placeholder (reported on stdout);
- **root** `docs/index.md` gets `okf_version`; sub-folder indexes are frontmatter-free;
- lists **every** direct subfolder (non-recursive) under `## Subfolders` — links the ones that have their own `index.md`, marks the rest `(no index yet)`; skips hidden/transient dirs (`.git`, `node_modules`, …);
- **idempotent + byte-stable** (no timestamps): re-running with no doc change writes nothing;
- `--check` exits 1 (writes nothing) if the index would change — for hooks / audits.

## Process

**Step 0 — resolve the folder.**
If the prompt names a folder, use it. **If no folder is given, ask which folder** (offer the
detected `docs/` subfolders as options). Do not guess.

**Step 1 — generate/refresh the skeleton.**
Run `python3 scripts/gen_index.py <folder>`. It writes/updates `index.md` and prints a
`NEEDS SUMMARY` list of docs with no summary yet.

**Step 2 — summarise each doc concisely (only those in `NEEDS SUMMARY`).**
For each listed doc: read it, and write **one concise sentence** capturing what the document is.
**Preferred:** write it into that doc's own OKF `description:` frontmatter field (reusable,
OKF-native, becomes the single source of truth). **Fallback** (if you must not edit the doc):
put the sentence directly in the `Summary` cell of `index.md`. Keep it terse and specific — the
instance, not the type ("KOGU prior-auth classification flow", not "a use case").

**Step 3 — finalise.**
If you wrote descriptions into docs, re-run `python3 scripts/gen_index.py <folder>` so the index
is fully script-derived and byte-stable. Confirm no `_TODO summarize_` remain.

**Step 4 — report.** State which docs were added, removed, or summarised.

## Output format (always this shape)

```markdown
# <folder>/ — index

<!-- OKF reserved index — generated by util-docs-index … -->

| Type | Document | Status | Summary |
|---|---|---|---|
| Persona | [Personas](01a-personas.md) | active | The people we serve — Tier-1 archetypes. |

> N document(s)
```

The bundle root additionally opens with `---\nokf_version: "0.1"\n---`.

## Idempotency & enforcement hooks

- **Re-runs are byte-stable** — safe to run repeatedly; only real doc changes cause a diff.
- `--check` is the mode a **pre-commit hook** or **the `metamodel` skill's Audit mode** uses to detect a
  stale index without mutating anything (exit 1 = would change).

## Checklist

- [ ] Target folder resolved (asked the user if the prompt didn't name one).
- [ ] `gen_index.py` run; `index.md` written/updated.
- [ ] Every doc has a concise summary — no `_TODO summarize_` left (preferably via each doc's `description:`).
- [ ] Re-run is `unchanged` (byte-stable) after summaries are in place.
- [ ] Root `docs/index.md` carries `okf_version`; sub-folder indexes are frontmatter-free.
- [ ] `index.md` has no artefact frontmatter block (it is an OKF reserved file).
